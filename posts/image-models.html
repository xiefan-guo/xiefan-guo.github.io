This article surveys image models for both generation and editing, covering open-weight foundation models, proprietary models, and commercial products. The catalog prioritizes families represented on Artificial Analysis and Arena, alongside other documented industrial releases such as Canva Craft. Each family is accompanied by its official release posts, model technical reports, system cards, code, weights, and documentation where available.

Start with the model map or the live leaderboards. Each organization’s materials follow its section. Sources were reviewed on 27 October 2026; years attached to living documentation indicate the version consulted. Historical releases remain included with their documented availability.

3. OpenAI: DALL·E and GPT Image

The DALL·E paper describes autoregressive generation over text and image tokens. DALL·E 2 adds a prior that predicts CLIP image embeddings and a diffusion decoder conditioned on those embeddings. The DALL·E 3 report studies training with descriptive synthetic captions and evaluates their effect on prompt following.

The release history includes 4o image generation in March 2025, GPT Image 1 in the API in April, GPT Image 1.5 in December, ChatGPT Images 2.0 in April 2026, and ChatGPT Images 2.5 in September 2026. The Images 2.0 system card separately describes Thinking mode, which adds reasoning and tools, including web search, to the image-generation workflow.

GPT Image 1 mini, released on 6 October 2025, is a lower-cost generation and editing model with text and image inputs.

The 2.5 API model IDs are gpt-image-2.5-flare and gpt-image-2.5-sunburst. OpenAI positions Flare for speed and Sunburst for tasks requiring precise editing. Both accept text and image inputs and return images. The generation guide documents access through the Image API and the Responses API image tool; the tool guide also documents automatic prompt revision and editing across conversation turns.

Historical releases have different availability. OpenAI’s deprecation schedule records the shutdown of gpt-image-1 on 23 October 2026 and schedules gpt-image-1-mini, gpt-image-1.5, and chatgpt-image-latest for removal on 1 December 2026.

The earlier DALL·E 2 preview system card and DALL·E 3 system card document deployment evaluations, limitations, and mitigations alongside the generation-method reports.

4. Google: Nano Banana and Imagen

Nano Banana is the Gemini image family

Gemini 2.5 Flash Image, launched on 26 August 2025, introduced the original Nano Banana model after Google's earlier Gemini 2.0 native-image experiments. Nano Banana Pro followed on 20 November 2025 as Gemini 3 Pro Image; Nano Banana 2 followed on 26 February 2026 as Gemini 3.1 Flash Image.

The family also includes Nano Banana 2 Lite, named Gemini 3.1 Flash Lite Image, and Nano Banana 2.1. Their Lite model card and 2.1 model card were published on 30 June and 6 October 2026, respectively. The current API guide identifies 2.1 as gemini-nano-banana-2.1 and documents generation, conversational editing, and Google Search grounding at 1K, 2K, and 4K. The same guide limits Lite to 1K output, excludes Search grounding, and says it is not optimized for multiple references or sequential editing. These distinctions belong to the individual versions.

The historical Gemini 2.0 Flash model card records experimental image output. The Gemini 2.5 Flash / Flash Image card covers the original Nano Banana’s generation and editing evaluations, including character and style consistency and multi-image composition.

Imagen: Generation and specialized editing

The original Imagen paper combines text representations from pretrained language models such as T5 with diffusion-based image generation. Later primary materials include the Imagen 3 report and the Imagen 4 model card; the latter describes Imagen 4 as a latent diffusion model. Google's Gemini API migration notice now states that Imagen is unavailable through that API and directs developers to Nano Banana. The Vertex AI lifecycle documentation below separately records the discontinued Imagen 3 editing endpoint.

Vertex AI historically documented imagen-3.0-capability-001 for masked insertion, removal, outpainting, background changes, and reference-based customization. This was a different endpoint from Imagen 3 Generate, and its documented discontinuation date is 30 June 2026. Gemini / Nano Banana provides the current conversational generation-and-editing route.

5. Microsoft: MAI-Image

Microsoft introduced its first in-house image model, MAI-Image-1, in October 2025, followed by MAI-Image-2 in March 2026. Its MAI-Image-2e (Efficient) variant followed in April. The 2 June 2026 announcement released both MAI-Image-2.5 and MAI-Image-2.5-Flash for generation and editing. MAI-Image-2.5-Pro entered public preview on 23 July. The 2.6 model card records separate release dates: 14 August for MAI-Image-2.6 and 4 September for MAI-Image-2.6-Flash.

That card describes a diffusion-based architecture trained with a flow-matching loss and lists 20B non-embedding parameters. It supports text and image inputs and specifies a maximum output area of 2,359,296 pixels, equivalent to 1536 × 1536. Microsoft's September announcement documents multi-image reference editing, web grounding, and dynamic aspect ratios for both 2.6 variants, with access through MAI Playground and a Microsoft Foundry public preview. The accompanying data summary describes the training-data categories.

6. Reve

The September 2025 Reve release combined image creation, natural-language editing of generated or uploaded images, and remixing with multiple references. Arena retains editing entries named Reve v1, v1.1, v1.1 Fast, and Edit Fast. These historical evaluation names are distinct from Reve Image 1.0; the available release materials do not establish an exact dated backend for every label.

Reve v1.5 was released as an early version in February 2026; its announcement describes native-pixel-space generation at 4K. Reve 2.0 followed on 3 June. In The layout bet, the team describes an intermediate representation made of hierarchical regions, each with a location, size, local description, and optional image references or colors. Its model produces this layout before rendering pixels, and users can edit the structure or give natural-language instructions.

Reve 2.1 was announced on 9 July 2026. The 14 July API release separated ready-to-use image generation and editing from endpoints for layout creation, editing, and rendering. These announcements describe historical releases: Reve's service notice says new image and video creation ended after 27 September 2026, with existing assets downloadable from the web and mobile apps until 31 October.

7. Tencent: HunyuanImage and SRPO

Tencent’s releases include Hunyuan-DiT and HunyuanImage-2.1. The 2.1 repository describes a 17B diffusion model supporting 2K output, with a multimodal text encoder, a character-aware encoder, and a separate refinement stage. It also provides prompt-enhancement and distilled inference components.

The HunyuanImage 3.0 report describes a mixture-of-experts backbone with over 80B total parameters and approximately 13B activated per token. It combines autoregressive text prediction with diffusion over VAE image features. The January 2026 Instruct release adds image-conditioned generation and editing; the accompanying Instruct-Distil checkpoint recommends eight inference steps.

HunyuanImage 3.5 preview was announced on 22 September 2026. Tencent’s launch post highlights text rendering, complex layouts, realism, and consistency across edits. It describes text-to-image generation, reference inputs, and conversation-based editing, with up to five reference images and 2K output in the launch configuration.

The Tencent Cloud API guide documents a separate serving configuration for hy-image-v3.5-preview: a messages interface, optional external search, and up to 20 images across the supplied conversation. Explicit size values allow 4K output, while the automatic generate_max_pixels tiers stop at 2K. The WorkBuddy announcement documents the preview’s integration into that application.

The same Tencent Cloud service also documents hy-image-v3, which accepts text and up to three reference images. This hosted configuration and the open HunyuanImage-3.0-Instruct checkpoint appear separately in benchmark results; their names alone do not establish identical weights or inference settings.

Tencent also releases SRPO, a text-to-image checkpoint obtained by preference-tuning FLUX.1-dev. Its report introduces Direct-Align and semantic relative preference optimization to adjust diffusion trajectories with text-conditioned rewards. The release includes a full transformer checkpoint, inference and training code, and a ComfyUI workflow. Inference loads the SRPO transformer into the FLUX.1-dev pipeline; the published checkpoint supports generation.

8. Alibaba: Qwen-Image, Wan, and Z-Image

Qwen-Image: Generation, editing, and layers

The original Qwen-Image release uses a 20B multimodal diffusion transformer (MMDiT). The initial editing checkpoint conditions on both Qwen2.5-VL image features and VAE image latents. Edit-2509 adds multi-image editing and conditioning on depth, edge, and keypoint maps. Edit-2511 and the generation checkpoint Qwen-Image-2512 followed in December 2025.

Qwen-Image-Layered decomposes an RGB image into a variable number of RGBA layers using an RGBA-VAE and a variable-layer MMDiT. Its release post demonstrates editing individual layers; the repository specifies that the released weights are fine-tuned for image-to-multiple-layer decomposition and have limited text-to-multiple-layer generation capability.

The Qwen-Image-2.0 report describes unified generation and editing with Qwen3-VL conditioning and an MMDiT backbone. The 3.0 launch on 21 July 2026 reports support for longer instructions, dense layouts, and multilingual text.

The 2.0 API documentation separately records Qwen-Image-2.0’s 3 March 2026 snapshot and 2.0-Pro snapshots dated 3 March, 22 April, and 22 June 2026. Both support text-to-image generation and image editing; the dated API names identify hosted releases rather than downloadable checkpoints.

Qwen-Image-2.1 was released on 20 September 2026, after 3.0. Its visual generator has 7B parameters, alongside a separate Qwen3-VL text encoder; it supports RGBA generation and editing and up to ten reference images. The repository records the eight-step Turbo release on 9 October and identifies the Qwen Research License Agreement. The hosted API reference separately lists 3.0/3.0-Pro and 2.1-Pro/2.1-Turbo, with generation, editing, and direct or agent-based prompt enhancement.

The original family uses separate Qwen-Image-Edit checkpoints, while Qwen-Image-2.1 and Turbo share generation and editing in one model. The released 2.1 implementation supports local changes indicated by circles, painted annotations, or separate mask images, alongside RGBA editing and subject extraction. The hosted OpenAI-compatible API documents image-conditioned generation but does not expose a mask parameter.

The earlier hosted family included generation endpoints Qwen-Image-Plus and Max, and separate Edit-Plus and Edit-Max endpoints. Alibaba’s release history records Plus’s 9 January 2026 snapshot, Edit-Plus snapshots from 30 October and 15 December 2025, and Edit-Max’s 16 January 2026 snapshot. These hosted IDs are distinct from the downloadable Edit-2509 and Edit-2511 checkpoints. Alibaba’s retirement notice lists these legacy API endpoints for withdrawal on 10 October 2026, with Qwen-Image-3.0 as the replacement; their leaderboard entries remain useful historical records.

Qwen-Image: Autoencoders, post-training, prompt enhancement, and agents

The Qwen-Image-VAE-2.0 report studies high-compression image autoencoders with global skip connections, expanded latent channels, and semantic alignment. Its OmniDoc-TokenBench evaluates document-image reconstruction and text preservation with pixel, perceptual, and OCR-based metrics. The released dataset contains approximately 3,000 Chinese and English document crops.

The 2.0-RL report describes task-specific visual reward models, GRPO-based optimization, and on-policy distillation that merges generation and editing policies. Qwen-Image-Flash separately studies few-step distribution matching distillation, examining the training-data mix, teacher guidance, and the balance between generation and editing tasks. The reference below uses the Flash paper’s September 2026 revision.

Qwen-Image-PE learns to turn short requests into detailed visual specifications before image generation. Caption-Based Reverse Distillation (CRD) trains the enhancer on dense captions of selected images. Groupwise Design Reward (GDR) then compares candidate images for the same request across lighting, composition, layout, and detail; these scores and an alignment reward train the enhancer with GRPO while the image generator remains frozen.

The paper reports Qwen-Image-Bench Overall scores of 60.28 for the 9B enhancer and 62.17 for its internal 397B model, versus 54.36 for original requests, using the same Qwen-Image-2.1 generator. It also evaluates transfer to FLUX.2-dev, Krea 2 Turbo, HunyuanImage-2.1, and FLUX 3 Image Klein. The released 9B checkpoint is named Qwen-Image-2.1-PE-T2I; its model card and official inference code describe prompt rewriting with an enhanced prompt and recommended aspect ratio.

The Qwen-Image-Agent paper describes planning, reasoning, search, memory, and feedback around image generation. It introduces Image Agent Bench (IA-Bench), with 730 instances and 1,801 binary checklist items covering the Plan, Reason, Search, and Memory capabilities. This benchmark assesses the agent workflow; OmniDoc-TokenBench assesses image reconstruction.

Qwen-Image-Bench: Evaluation for image creation

Qwen-Image-Bench evaluates generated images across five dimensions: quality, aesthetics, alignment, real-world fidelity, and creative generation. Its hierarchy contains 23 sub-capabilities and 56 detailed evaluation criteria, including text rendering, design applications, and visual storytelling. The prompt set contains 1,000 items, split evenly between long and short prompts, each available in Chinese and English.

The released Q-Judger is an evaluator trained with expert annotations: it takes a prompt and generated image and returns structured scores against the criteria. Its scoring protocol maps fail, pass, and excel to 0, 60, and 100, excludes non-applicable criteria, and aggregates through the hierarchy. The official toolkit provides judge inference and score computation, alongside released benchmark data and results for 18 models.

Wan-Image and Wan-Weaver: Generation, editing, and interleaved output

The earlier hosted releases used separate task interfaces. Wan2.5 provided wan2.5-t2i-preview for generation and wan2.5-i2i-preview for editing. Wan2.6 has a dedicated wan2.6-t2i model, while wan2.6-image supports editing and interleaved text–image output. Its editing mode accepts one to four images; its interleaved mode accepts text alone or one reference image. These are distinct interfaces behind the Wan2.6 entries on generation and editing leaderboards.

The Wan-Image report describes a unified model with an MLLM-based Planner and a diffusion-transformer Visualizer, together with an RGBA-capable VAE, prompt enhancement, and an image refiner. It documents data curation, staged training, Cascade RL for preference alignment, and sampling-step distillation. Its evaluations cover text-to-image generation, reference-based and interactive editing, and coherent image series. These technical details complement the Wan2.7-Image release and API materials.

The related Wan-Weaver paper studies interleaved text–image output by training the planner with textual proxies for visual content and the visualizer with reference-guided image data. The Wan-Image report cites this planner–visualizer design. It also identifies DenseGRPO, which estimates reward gains at individual denoising steps, as one component of Cascade RL.

Alibaba announced Wan2.7-Image and Wan2.7-Image-Pro on 1 April 2026. Its launch materials describe color codes and palette proportions in prompts, reference inputs, local edits, and image sets. The API documentation limits Pro’s 4K output to single-image text-to-image generation; editing and image-set generation support up to 2K.

Z-Image: Base and distilled variants

The Z-Image report describes a 6B scalable single-stream diffusion transformer. Its repository combines text, visual-semantic, and VAE tokens in one input stream and lists released Z-Image and Z-Image-Turbo checkpoints, with 50-step and eight-step configurations respectively. The same model table lists Z-Image-Omni-Base and Z-Image-Edit with weights marked “To be released”.

The team’s later Z-Reward report studies reasoning-conditioned score distributions and their distillation into a smaller visual reward model. It is a separate reward-model study, rather than a new Z-Image generation checkpoint.

12. Stability AI: Stable Diffusion

The latent diffusion paper describes diffusion in the compressed space of a pretrained autoencoder, with cross-attention for conditioning inputs such as text. SDXL develops this approach with a larger U-Net, a second text encoder, additional conditioning, and a separate refinement model. Adversarial diffusion distillation, used for SDXL Turbo, combines a diffusion-teacher signal with an adversarial loss to train a model for one to four sampling steps.

The SD3 report studies rectified-flow training and a transformer with separate text and image weights and attention that exchanges information between the two modalities. Stable Diffusion 3.5 includes Large, Large Turbo, and Medium. Stability AI lists 8.1B parameters for Large and 2.5B for Medium; Large Turbo is distilled for four-step generation. The release provides downloadable weights and inference code under the version's stated licensing terms.

The separate latent adversarial diffusion distillation (LADD) report studies SD3-Turbo, distilling the 8B Stable Diffusion 3 model into four unguided sampling steps. This complements the earlier ADD paper for SDXL Turbo.

Editing is represented by specialized checkpoints and service endpoints. The Stable Diffusion 2.0 release included a text-guided inpainting model fine-tuned from its base generator. Stability AI later packaged inpainting, outpainting, removal, and related editing operations as Stable Image services. Its inpainting guide specifies an input image, a mask, and a prompt. 34. Shanghai AI Lab: Lumina

The family’s earlier reports include Lumina-T2X, which introduces Flag-DiT, and Lumina-Next, which develops Next-DiT and resolution extrapolation. The original Lumina-mGPT establishes the autoregressive branch through multimodal generative pretraining and progressive fine-tuning.

A small autoregressive output head predicts the codes within each visual position while the backbone processes positions in parallel. The report evaluates image generation and editing; the project and repository provide the associated release materials.

35. Kuaishou: Kolors and Kling Image

Kolors is Kuaishou’s latent-diffusion text-to-image model supporting Chinese and English prompts. The official repository provides inference code and weights, together with inpainting, ControlNet, IP-Adapter, FaceID, and LoRA training and inference materials.

Kolors’ machine assessment uses the Multi-dimensional Preference Score (MPS). Its separate evaluation-method paper models aesthetics, semantic alignment, detail quality, and overall human preference.

Kolors-Inpainting is a separate checkpoint initialized from Kolors, with additional U-Net inputs for the masked image and mask. It performs prompt-guided replacement within selected regions. These hosted image products should be distinguished from the open Kolors checkpoints and from the separately named Kling video models.

37. BAAI: OmniGen and Emu

OmniGen and OmniGen2: Instruction-aligned multimodal generation

The original OmniGen unifies text-to-image generation, editing, subject-driven synthesis, and other visual conditions within one diffusion model and instruction interface.

Emu: Next-token modeling and native multimodality

The original Emu autoregressively predicts text tokens and continuous visual embeddings. Emu2 scales this approach and studies in-context image generation from visual examples. Their shared repository contains the earlier code and checkpoints.

Emu3 models text, images, and video as discrete token sequences with an autoregressive transformer. The Emu3.5 report describes multimodal pretraining, reinforcement-learning post-training, and discrete diffusion adaptation (DiDA) for accelerated generation.

The Emu3.5 release distinguishes the general interleaved model from Emu3.5-Image, which is specialized for single-image text-to-image and any-to-image tasks. Its X2I interface accepts one or more reference images for image-conditioned generation and editing. The released checkpoints still use next-token prediction; the repository lists DiDA-accelerated weights separately as forthcoming.

43. Model interfaces and release boundaries

Generation and editing are version-specific. Early Qwen releases use separate generation and Edit checkpoints, while Qwen-Image-2.1 supports both. FLUX.1 Fill is a masked editor; Kontext uses image context and instructions. The model map identifies these interfaces separately.

Product features can combine several models. Recraft’s natural-language editing workflow uses external editing models. Canva’s Craft and Magic Layers handle generation and design reconstruction respectively. A product’s editing controls therefore need to be read alongside its model documentation.

Weights, adapters, and inference modes are different releases. FireRed Lightning is a LoRA loaded onto a base editor. Krea 3 Fast, High, and Ultra are API modes, and Ultra requires an image input. NVIDIA’s Cosmos image checkpoints and agentic configuration likewise have separate release and evaluation documentation.
